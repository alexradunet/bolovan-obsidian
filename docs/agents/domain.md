# Domain Docs

This repository uses a single-context domain-doc layout.

## Before exploring

Read the root `CONTEXT.md` and any relevant ADRs under `docs/adr/`. If either is absent, proceed without proposing placeholder documentation.

## Use the glossary

Use terms from `CONTEXT.md` in issue titles, acceptance criteria, tests, and design work. Avoid introducing synonyms for established domain concepts. A missing concept may justify domain-modeling work, but only when the task needs that concept.

## Respect architectural decisions

Surface any conflict with an existing ADR explicitly rather than silently overriding it.
